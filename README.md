# The Lost Systems — an API Investigation Campaign

A Business Analyst's case files: narrative missions where you play a consultant investigating a broken system, working only from stakeholder messages and technical artifacts. No code is written. The point is to build real fluency with how APIs work by reasoning through incidents the way a BA actually would on assignment.

See RULEBOOK.md for the locked mission format. It only changes if I explicitly ask for a revision, versioned in that file's changelog.

## Why this exists

I'm a Business Analyst, not a developer. This repo is a self-directed learning project to build real, practical fluency with how APIs and system integrations work, the kind of understanding that lets a BA ask sharp questions, read documentation, and write requirements that hold up, without writing production code.

Each episode is a short investigation: a stakeholder reports a problem, I get one technical artifact (real API documentation, sometimes against a live public API), and I have to reason through it like a consultant would on day one of an assignment. Skills this builds toward: reading REST API documentation, understanding request/response mechanics and status codes, authentication and token flows, webhooks vs. polling, and translating technical incidents into BA deliverables (research questions, requirements, acceptance criteria).
